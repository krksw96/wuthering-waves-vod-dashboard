# Lark 원본 연결 및 자동 업데이트

원본은 `https://ojpvaupdkdbj.jp.larksuite.com/wiki/TjncwLOoOi0Ds2kBpiKjKetSpH4?sheet=4z1yjS`입니다. 이 문서와 코드는 연결을 위한 준비물입니다. 원본 읽기 권한이 아직 확인되지 않았으므로 현재 미리보기는 원본 데이터의 동기화 완료를 의미하지 않습니다.

## 원본 읽기 권한 연결

1. 원본에 접근 가능한 조직의 Lark 내부 앱을 준비합니다. JP Lark 원본이므로 기본 API 주소는 `https://open.larksuite.com`입니다.
2. 앱에 Wiki 노드 조회와 전자표 읽기 권한을 부여하고, 해당 앱이 원본 Wiki/시트를 읽을 수 있도록 문서 접근 권한을 설정합니다. API scope와 원본 문서의 공유 권한은 각각 필요합니다. 원본에 대한 쓰기 권한은 사용하지 않습니다.
3. 서버 또는 GitHub 저장소의 Secrets에 `LARK_APP_ID`, `LARK_APP_SECRET`을 저장합니다. 값은 브라우저 코드, `config/source.json`, Git 커밋에 넣지 않습니다.
4. 앱 권한과 원본 헤더를 확인한 뒤 `npm run sync -- --dry-run`으로 전체 읽기와 변환을 검사합니다. `--dry-run`도 온라인 모드에서는 원본을 읽지만 데이터 파일은 바꾸지 않습니다.
5. 결과의 영상 수, 날짜 범위, 첫 행과 마지막 행, 조회수/좋아요 빈 값, 주제와 버전을 실제 시트와 대조한 뒤 `npm run sync`를 실행합니다.

개인 사용자 토큰을 사용하는 일회성 검사에서는 `LARK_USER_ACCESS_TOKEN`을 환경 변수로 전달할 수 있습니다. 이 토큰이 있으면 앱 인증보다 우선합니다. 사용자 토큰은 만료되므로 지속적인 자동화에는 내부 앱 자격 증명을 사용합니다. 스크립트가 기존 브라우저나 CLI의 인증 정보를 추출하거나 권한을 우회하지 않습니다.

## 최초 헤더 매핑

스크립트는 전체 열을 읽고 첫 30행에서 한국어·중국어·영어 헤더를 찾습니다. KOC, 게시일, 영상 링크 또는 제목이 필요합니다. 동일한 의미의 열이 여러 개면 임의로 선택하지 않고 오류를 반환합니다. 실제 원본에 맞춰 `config/source.json`의 `headerRow`와 `columnMap`을 설정할 수 있습니다.

다음은 **형식 예시이며 실제 원본 열 위치가 아닙니다.**

```json
{
  "headerRow": 2,
  "columnMap": {
    "creator": "B",
    "title": "D",
    "url": "E",
    "date": "G",
    "views": "H",
    "likes": "I",
    "topics": "J",
    "version": "K",
    "format": "F"
  }
}
```

`headerRow`는 1부터 시작하는 실제 행 번호입니다. 열은 대문자 열 문자, 0부터 시작하는 열 번호, 유일한 헤더 이름 중 하나로 지정합니다. 지정하지 않은 필드는 헤더에서 계속 찾습니다. 전체 열을 명시한 경우 `headerRow`도 명시하세요.

게시일은 `YYYY-MM-DD`, `YYYY/MM/DD`, `YYYY.MM.DD`, 한중 날짜 표기, Excel 날짜 일련번호를 처리합니다. 시간대가 포함된 ISO 시각은 설정한 `timeZone`의 날짜로 변환하며 기본값은 `Asia/Seoul`입니다. `01/02/2026`처럼 모호한 날짜는 추측하지 않습니다. 원본이 월/일/년이면 `dateOrder`를 `MDY`, 일/월/년이면 `DMY`로 설정합니다.

조회수와 좋아요는 공개된 원본 값을 읽습니다. 빈 값, 비공개 또는 해석할 수 없는 값은 `null`로 남고 실제 0과 구분합니다. `1,234`, `1.2K`, `2만`, `1.5万` 같은 표기를 정규화합니다. 주제는 쉼표·세미콜론·줄바꿈·`|`로 나뉜 원본 태그를 사용하고, 없으면 `미분류`로 표시합니다. 제목을 보고 주제를 임의로 추정하지 않습니다.

버전은 원본 버전 열을 우선합니다. 원본에 버전이 없으면 `config/source.json`의 `versions`에 확인된 버전별 시작일·종료일을 명시할 수 있습니다. 버전 날짜가 비어 있는 기본 설정은 임의의 출시 일정을 사용하지 않습니다. 겹치는 버전 기간은 거부합니다.

## CSV/JSON으로 원본을 가져오기

사용자가 직접 내보낸 실제 파일을 가져올 때는 네트워크 없이 다음 명령을 사용할 수 있습니다. 원본 파일은 저장소 외부의 안전한 로컬 경로에 두세요.

```powershell
node scripts/sync-lark.mjs --input "C:\원본보관폴더\koc-export.csv" --dry-run
node scripts/sync-lark.mjs --input "C:\원본보관폴더\koc-export.csv"
```

JSON은 2차원 셀 배열, `values` 배열, Lark `valueRange.values`, 또는 `lark-cli sheets +table-get`의 `columns`/`data` 결과를 지원합니다. 여러 시트가 든 JSON은 임의로 첫 시트를 선택하지 않으므로 대상 시트 하나만 내보내세요. CSV에는 헤더와 전체 데이터 행이 있어야 합니다. 수동 내보내기에 없는 링크·숨겨진 행·버전 정보는 복원하지 않습니다.

오프라인 가져오기는 `source.status=imported`, `importedAt`으로 기록합니다. 온라인 API 읽기가 끝난 경우에만 `source.status=connected`, `syncedAt`이 기록됩니다. `generatedAt`은 변환 시각이며 영상 지표가 측정된 개별 시각을 의미하지 않습니다.

## 자동 갱신 활성화

저장소 최상위 `.github/workflows/sync-koc-lark.yml`은 UTC 기준 매일 00:17, 06:17, 12:17, 18:17에 실행하도록 준비되어 있습니다. 한국 시간은 09:17, 15:17, 21:17, 03:17이고 중국 시간은 08:17, 14:17, 20:17, 02:17입니다. GitHub 실행 상황에 따라 시작이 지연될 수 있습니다.

기본 상태에서는 `KOC_LARK_SYNC_ENABLED` 저장소 변수가 없으므로 작업이 건너뛰어집니다. **Secrets를 등록하고 첫 실제 동기화를 검증한 뒤** 저장소 Actions Variables의 `KOC_LARK_SYNC_ENABLED`를 문자열 `true`로 설정하세요. 이후 수동 Run workflow로 실제 원본 읽기, 데이터 커밋, 사이트 반영을 한 번 확인합니다.

정상 실행은 테스트 → 전체 원본 읽기 → 정규화·검증 → `data/koc-data.json` 커밋 → 일반 push → GitHub Pages 재빌드 요청 순서입니다. 이 워크플로는 기본 브랜치에서 사이트를 만드는 GitHub Pages 설정을 전제로 합니다. Pages 자체는 저장소에서 먼저 활성화해야 합니다. `contents: write`는 데이터 커밋용, `pages: write`는 Pages 재빌드 요청용입니다. Actions 토큰의 커밋만으로 별도의 Pages 배포가 시작된다고 가정하지 않습니다. 재빌드 요청 성공은 배포 완료와 다르므로 Pages 배포 상태도 확인하세요.

사이트는 기존 저장소의 `koc/` 하위에 배치되어 있고, 워크플로의 실행 폴더도 `koc/`입니다. 따라서 `git add data/koc-data.json`은 저장소의 `koc/data/koc-data.json`만 추가합니다. 다른 저장소로 복사할 때에는 이 작업 폴더 설정과 Pages 게시 경로를 함께 확인하세요.

## 실패 시 동작과 집계 범위

- 모든 그리드 행을 배치로 읽어 중간 공백 아래의 영상도 포함합니다. 요청 한도, 권한 오류, 빈 결과 또는 해석 실패가 발생하면 마지막 성공 파일을 바꾸지 않습니다.
- 기본값은 유효하지 않은 행이 10%를 넘거나 기존 실제 원본 영상 수가 40% 넘게 줄면 갱신을 중단합니다. 원본 행 삭제나 양식 변경이 의도된 것인지 확인한 후 관련 설정을 조정하세요.
- 중복 YouTube ID/링크는 한 영상으로 집계하며 마지막 원본 행을 완전한 기록으로 사용합니다. 중복 행의 조회수만 최대값으로 합치는 등 실제로 존재하지 않는 스냅샷을 만들지 않습니다.
- 출력에는 KOC·영상·게시일·공개 지표·주제·버전·형식·출처 행만 포함합니다. 연락처·계약·계좌 등 다른 원본 열은 배포 데이터에 내보내지 않습니다.
- 이 사이트는 **선택 기간에 게시된 영상의 원본에 기록된 누적 조회수와 좋아요**를 보여줍니다. 기간 중 새로 발생한 조회수·좋아요 증가량은 별도 시점별 스냅샷 없이는 계산하지 않습니다.
- 동기화는 Lark의 최신 값을 읽습니다. 원본 시트 자체의 조회수·좋아요 갱신이나 YouTube 직접 수집을 수행하지 않습니다.
